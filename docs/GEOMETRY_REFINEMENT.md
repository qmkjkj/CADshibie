# 原图几何精修与融合修复（2026-11-26）

更新：带标签数据恢复后，前 100 张校准图上的来源隔离、canonical 与原图平移分支均未通过验收，默认已恢复历史选择路径。后续结论以 [带标签优化记录](LABELED_DATA_OPTIMIZATION.md) 为准，以下保留原型实现时的记录。

本轮按 [架构路线图](PQ_ARCHITECTURE_ROADMAP.md) §7 的路线 A 实现可运行的最小原型，并修复 §3.2 指出的融合栅格差异。历史真实数据基线仍是 **PQ 24.348%**；本轮没有带标签数据，尚无新的真实 PQ 结果。

结合 [优化方案](OPTIMIZATION_PROPOSAL.md) §8 与 [优化记录](OPTIMIZATION.md) §17–23，当前优先处理实例归属及原分辨率几何。旧模板框内拟合、只改长切段、简单放开类别抑制已有负结果，不把它们作为本轮默认变更。512 ROI、独立 Stuff、原子归属也已经存在，不重复宣称为新增方法。

本轮代码改动：

- `cadvec/hybrid.py` 的实例门控和并集按完整来源身份分组，避免不同引擎的同号实例共享决策；简单双引擎融合的去重限定在同类别，并移除固定实例 ID 偏移。
- `--hybrid-raster canonical1000` 用共用 PIL/1px 渲染替代 400px OpenCV 折线近似，正确处理圆、椭圆及实际画布尺寸。默认保留 `legacy400` 供对照；来源身份修复直接生效。
- `cadvec/geometry_refine.py` 对现有 Thing 实例搜索原图 ±2px 的整体平移。原图 RGBA 提供可见前景及中心线，证据窗口固定；以完整独立图元比较双向截断距离，并检查逐图元支撑、原始前景支撑、近似等分、越界与其他实例冲突。所有图元一起移动，类别、身份、图元类型和数量保持不变，Stuff 不参与。
- 局部渲染保持全局 PIL 像素相位；候选导出后的渲染必须与评分时的候选掩码一致，否则回退。PIL 二值掩码也统一为 0/1 布尔存储，确保原生图像算子接收规范布尔输入。

运行对照时使用不同输出目录，不覆盖原基线：

```powershell
# 仅来源身份修复，仍用旧栅格、关闭几何精修。
.venv\Scripts\python.exe infer.py --input <PNG目录> --output _work/identity_fixed

# 仅切换融合渲染。
.venv\Scripts\python.exe infer.py --input <PNG目录> --output _work/canonical --hybrid-raster canonical1000

# 在上述基础上打开原图几何精修。
.venv\Scripts\python.exe infer.py --input <PNG目录> --output _work/refined --hybrid-raster canonical1000 --geometry-refine
```

诊断写入输出目录的同级 `<输出目录名>_geometry_refine/`，记录原分数、候选分数、逐图元支撑、平移和接受/拒绝原因。推理摘要记录生效栅格与精修实例数。诊断不进入比赛 JSON。该精修在每次推理末尾执行一次，不能反复对输出累积平移。

已验证：96 项测试通过；新增用例覆盖已知偏移恢复、原本对齐不动、缺失短图元拒绝、邻近实例冲突、平行线歧义、非方形原图/画布、曲线指令、透明彩色笔画及局部栅格相位。合成的 1px 邻近实例在旧去重中丢失一个，新模式保留两个；已知平移案例从严格失配恢复匹配。这些结果验证具体机制，不代表真实数据 PQ。

一张真实 dev 图完成 canonical+精修的 GPU/离线入口检查，无异常。该图 8 个 Thing 实例均回退原几何，未为追求“修改数量”降低验收门槛。没有全量重跑 dev，也没有使用其预测或 manifest 作为监督。

后续带标签数据的用途：训练集用于训练 native 细节头及实例归属；按来源隔离的 calibration 用于选择参数；独立留出集用于比较严格 PQ、TP/FP/FN。原图中心线与评分四点几何可能不完全一致，因此原图拟合改善仍须经过有标签 PQ 验收。要兑现超过 50% 的目标，还需恢复更多完整实例；本轮的小范围平移不能补出不存在的候选或替代实例归属模型。
