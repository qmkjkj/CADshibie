# 方法说明：工程图纸 PNG 图元解析（v2）

> 2026-11-27 状态说明：本文保留早期 v2 与 hybrid 的方法记录。当前默认为 hybrid 加原生边界残差细节头，历史 1000 页回归 PQ 33.785%，清单总参数 23,561,566；当前实现与限制以 [README](../README.md)、[第三轮记录](ROUND3_NATIVE_GEOMETRY.md) 为准。后续尚未执行的路线见 [详细实施方案](NEXT_OPTIMIZATION_PLAN.md)。下文旧参数和旧默认描述按历史版本理解。

> `README.md`、`requirements.txt`、`weights/manifest.json`。

## 1. 任务与输出

输入 `dev_final` 的平面图 PNG，输出同名 12 字段 JSON：`commands`
（0 Line / 1 Arc / 2 Circle / 3 Ellipse）、`args`（每个图元 4 个二维采样点）、
`lengths`、`semanticIds`（0–34 前景，35 忽略）、`instanceIds`（Thing 非负，
Stuff/忽略类 -1）、`width`/`height`、`obj_cts`、`boxes`、`rgb`、`layerIds`、
`widths`。写盘前由 `cadvec/schema.py::validate_output` 严格校验。

## 2. 总体流程

v2 引擎（`infer.py --engine v2`，默认）是“精确颜色恢复 → 亚像素几何 →
平行线优化 → 对象假设 → GPU ViT 分类”的流水线：

1. **精确描边色恢复**。PNG 是透明底 + 抗锯齿细线，直接合成到白底会得到
   “描边色 × 覆盖率”的混合色，颜色语义随之失效。调色板（训练集 SVG 中
   197 种精确 `stroke` 色）中每个颜色定义一条从白色出发的射线
   `c = 255 + t·(s − 255)`；对每个前景像素在所有射线中取最近者，同时得到
   覆盖率 `t`。无彩色像素（黑/多种灰）按反混合亮度分桶，避免不同灰阶互相
   吞并。这一步把抗锯齿造成的颜色漂移基本消除。
2. **骨架折线几何**。每个颜色层独立骨架化，用 2 像素膨胀连通后标号，
   把骨架拆成若干**连通分量**（每个分量就是一个对象假设）。对每个分量沿
   骨架像素行走，在交叉点/端点处断开成折线，再按弧长等距取 4 个采样点
   （与赛题 GT 的采样方式一致）并按像素中心 +0.5 换算到画布。折线的忠实度
   很重要：实测 4 点采样后仍有约 18% 的真值实例达到 IoU>0.5，而
   Hough 直线重建方案只有约 4%。`cadvec/strokes.py` 中的直线/圆/椭圆拟合
   仍保留给笔画级流水线与圆弧符号分析。
3. **平行线优化**（`cadvec/parallel.py`）。工程图的可辨识对象大多由平行线
   组成：墙体/窗是平行长线，家具是矩形边，停车位是一排短平行线。
   - 对直线两两判定“平行且垂距合理且投影重叠”，用并查集聚成
     `ParallelRibbon`；按垂距排序后重新切分，防止传递闭包把整张图的水平
     尺寸线串成一条带；
   - 带内**端点对齐**：把同一平行线带的成员端点沿投影方向对齐到中位数，
     规整窗、家具轮廓；
   - 近水平/竖直直线吸附到精确方向（容差 1.2°），降低栅格评估的亚像素抖动。
4. **对象假设**。默认的对象假设就是第 2 步的颜色层骨架连通分量：同一符号
   的描边在图像空间相连，天然形成一个分量；跨色组合（彩色符号 + 黑色短边）
   由 `cadvec/objects.py` 的端点连通与平行线带逻辑补充（`group_parallel`
   开关，默认关闭——实验表明把平行分量并成实例反而降低 IoU）。
5. **ViT 语义分类**（`cadvec/vit.py`）。每个假设渲染 4 通道 224×224 裁剪：
   白底 RGB + 假设自身描边掩码，明确告诉模型“要判断的是哪几条线”。模型是
   从零训练的小型 ViT（patch16、宽 192、6 层、6 头，291 万参数），损失为
   类权重交叉熵；在 `RTX 3060` 上用 bf16 混合精度训练。训练样本由同一套
   几何流水线在 `train_final` 上生成，再用同名 SVG 真值按 IoU/覆盖率打
   标签（IoU>0.5 → 类别；覆盖率>0.6 → 实例组成部分；覆盖率<0.15 → 忽略类
   35），推理与训练分布一致。
6. **输出与实例**。置信度低于阈值的假设输出 35（按规则被评测跳过，避免
   误检）。同类别、包围盒相接的假设合并为一个实例（Thing 分配非负实例号）；
   Stuff 类别（30–34）按类别合并、实例号为 -1。重复绘制的同一线段只保留
   一条。

## 2.1 图元级全景检测（GAT）与 hybrid

在像素管线之外，新增图元级全景检测分支（`--engine gat`）：

- 节点=颜色层骨架折线，14 维特征（位置/长度/方向/颜色/线宽/曲率/密度）；
- 边=KNN(6)+端点邻近，4 维边特征；
- 4 层图注意力（4 头）+ 语义头（36 类）+ 邻接头（边两端同实例）；
- 训练：4000 张 PNG，恢复笔画与 SVG 图元按 50% 重叠匹配生成标签，
  30 轮 + 10 轮微调；
- 推理：邻居概率阈值化 + 同类并查集 → 实例，再与颜色先验、逐类策略、
  每图 top-K 结合。

逐类对比后，GAT 只在 class 8（盲窗）上稳定优于像素管线，因此最终提交
使用 **hybrid**（`--engine hybrid`）：

- 像素管线为底，class 8 与 GAT 做实例掩码并集（IoU>0.5 去重）；
- YOLOv8n-seg 接管 class {26,29,15,23,16,10,12}；
- 低精度类 {2,11,14,17,18,21,22,30,34} 抑制；
- **class 8 检测掩码门控**：YOLO-seg 的类 8 检测很准，而像素管线在无盲窗
  图纸上大量误报；融合后的每个 class 8 实例必须与 YOLO 类 8 掩码的
  重叠（交集/较小面积）>0.1，否则丢弃。全量 class 8 FP 2899→1362，
  TP 131→125，总 PQ +0.30，calib/holdout 同向。

### 2.2 ROI 实例墨迹细化（`cadvec/roi_ink.py`，GPU 训练/推理）

YOLO-seg 的掩码是 GT 实例凸包，框内混入墙线和文字，直接把整条笔画收进
实例会带来大量 FP。新增一个小 U-Net（1.95M 参数，192×192 输入、类别条件）：

- 输入：YOLO 检测框外扩 30% 的裁剪（白底 RGB）；
- 目标：该 GT 实例的墨迹，用与评测器一致的 PIL 栅格化（1px 线）；
- 输出：框内实例墨迹概率图 → 8 连通去噪 → 骨架 → 每 6 像素切成 4 点短折线
  （同一实例的所有折线并入一张掩码，因此比一条长折线更贴合 GT）；
- 与主引擎按实例掩码 IoU>0.5 做**并集**（保留两边，去重），不替换 v3/GAT；
- 训练数据：train_final 4000 张、10 个主要类别、约 1.24 万实例；GTX 3060
  20 轮、bf16，验证 Dice 0.767 / mask IoU 0.622；
- **实例几何质量门控**：墨迹总长、密度、长宽比等，calib 选阈值、holdout 验证
  （`weights/roi_ink_quality.json`），单模型下全量 11.804→13.244%；
- **256 分辨率模型**：`roi_ink_256.pt`（192→256 裁剪，13 类、1500/类、20 轮，
  Dice 0.801 / IoU 0.667）在 class 8/14/22/25 等明显更好；
- **按类路由**：class 2 用 192 主模型，其余 12 类用 256 模型，实例仍与主引擎
  并集、过几何质量门控；
- **学习式质量门控**：15 维 ROI 概率/几何特征，逐类逻辑回归；train_final 2000 张
  拟合，test 行级验证 ROI 类 PQ 33.48→38.20%；全量 16.250→16.886%；
- **class 2 专用模型**：全部 class 2 训练实例（5000 上限、192、30 轮，Dice 0.815），
  class 2 路由到该模型，TP 392→499；
- **统一类别条件模型**（`roi_ink_unified.pt`）：一个 256×256 U-Net，用类别
  one-hot 条件覆盖 0–29 全部 Thing 类；train_final 21,284 实例 + 4,926 个
  真实难负例（与任何 GT 框都不重叠的 YOLO 检测），24 轮，验证 Dice 0.760 /
  IoU 0.613。推理时作为第三套权重，默认只接管 class 26：全量 TP 32→72、
  FP 108→44、FN 101→61，总 PQ +0.533；
- **R1 数据卫生**：按 64 位 dHash 分组划分（train 3400 / val 600；calib 300 /
  hold 300 / final 400，970 个测试组），避免同源近似重复泄漏；`label_qa.json`
  显示 1000px 下无极小实例，但 300/400px 的稳定率仅 0–45%，故所有门控与评估
  统一用 raster 1000；
- **R0 损失归因**：Thing-only 在 1000px 下 FN 中 3048 为无候选、1119 为严重
  错位、1036 为 0.3–0.5 近阈值；FP 中 1036 与任何 GT 无重叠。class 3 有 819
  个 GT、YOLO 框覆盖 99%，说明“有框”不等于“墨迹能达到 IoU>0.5”，瓶颈在
  几何/矢量化而非分类；
- **几何往返诊断**（`tools/geom_roundtrip.py`）：对 497 个真实 GT 实例，256
  裁剪的严格命中率为 74.0%，384 为 80.3%，512 为 **86.3%**，原分辨率为 100%。
  据此把统一模型从 256 提升到 **512 等比缩放**，从 256 权重微调 10 轮；
- **512 统一模型**（`roi_ink_512.pt`）：默认接管 class 3/4/26/29，并修正质量
  门控的分组键（此前主引擎与 ROI 同号实例被错误合并，class 8 因此被误删）。
  全量相对上一版：class 3 +227 TP、class 4 +63 TP 且 FP −434、class 29
  FP −307、class 8 TP +46；
- **全图 Stuff 语义分支**（`stuff_unet.pt`）：30–34 五类、512 重叠分块、
  train_final 1,598 张含 Stuff 图纸训练；推理拼接回 1000px，每类按
  `instance=-1` 输出一条结构段。逐类阈值/最小面积在 calib 用全图
  TP/FP/FN 标定，hold/final 验证。全量 Stuff TP +120，Thing 不变；
- **精度再平衡**：512 模型扩到 class 22（FP 41→23，TP 不变），并抑制
  class 16/23（全量 TP 3、FP 182）；calib 选路由、hold/final 验证；
- **YOLO 锚点整实例重归属（B-lite）**：对 class 3/8/18/22/28，把现有实例
  整体挂到同类 YOLO 框锚点，合并重复实例；全量 FP 2966→2727，
  class 8 calib FP 269→178；不改几何、不改检测器；
- **原子级锚点归属（B-lite v3）**：class 3/28 的每个图元独立选择同类
  YOLO 锚点（12 维几何特征 + 共享逻辑回归，train_final 43.7 万对），
  按锚点分组生成实例；class 3 calib TP 59→70、class 28 27→30；
- 最终全量：PQ **24.348%**（SQ 68.137、RQ 35.734，TP/FP/FN=2186/2720/5143），
  R1 分组 calib 25.819%、hold 23.168%、final 24.083%，推理约 1.5s/张
  （含全部引擎、Stuff 分支、实例/原子级锚点归属）。

## 3. 合规、资源与可复现性

- **离线**：`infer.py` 启动即安装 socket 防护，评测不访问外部网络。
- **模型规模**：ViT 2,911,525 + YOLO-seg 3,399,033 + GAT 356,373 +
  ResNet18 特征主干 2,787,279 + 六套 ROI 墨迹 U-Net 各 1,948,847 +
  Stuff U-Net 1,929,971 = 23,077,263，远低于 5B；
  `compliance/params.py` 读取 `.pt` 状态字典求和并核对清单。
- **数据边界**：只使用主办方 `train_final`/`test_final` 的 SVG 训练与本地
  评估，`dev_final` 推理只读 PNG。
- **可复现**：依赖固定、种子固定；ViT 推理是确定性的前向计算，输出与线程
  数无关（`--workers` 只影响速度）。
- **GPU**：ViT 自动使用 CUDA（`--vit-device auto`），CPU 环境同样可运行；
  几何部分是 CPU 多线程。

## 4. 本地验证

见 `validation.json`：主结果在 `test_final` 全量 1000 张上按参考口径
（栅格 1000、IoU>0.5、匈牙利匹配）计算；另有 R1 感知哈希分组后的
calib 300 / hold 300 / final 400，其中 final 未参与任何模型、阈值或类别选择。
结果由 `cadvec/evaluate.py` 计算并写入 `validation.json`。该结果只用于本地
诊断，不是官方 `dev_final` 成绩（官方真值不公开）。

## 5. 已知限制

- 对象的实例边界仍由几何连通性决定，密集图里可能过分割/欠分割；
- 文字/标注线是主要误检来源，ViT 与置信度阈值只能部分抑制；
- GT 的 4 点采样会简化复杂符号，与像素级精确提取存在系统性差异；
- 未使用 OCR（任务不需要文字内容）。
